# 微笑花园 · 1.4.0

用于笔试展示的浏览器 AR 互动原型。当前版本已完成本地构建与自动验证；真实手机和多人验收范围见验证记录与真机验收表。

**在线体验：[微笑花园](https://urnotccw.github.io/smile-garden/)** · **公开源码：[urnotccw/smile-garden](https://github.com/urnotccw/smile-garden)**。电脑和手机浏览器可直接打开，首次体验需允许摄像头访问。

浏览器直播特效原型：微笑下雨，雨滴滋养蜡笔花园；张嘴大笑时烟花升空、成形并炸开，下降的粒子撞到头顶后反弹为爱心。手掌可接爱心、接雨，也能拨动花草。画面只在设备上处理，不上传、不录制，不请求麦克风。

## 运行与部署

安装 Node.js 18 或更新版本，在本目录执行：

```sh
npm start
npm test
npm run build
```

本地地址 http://localhost:4173 。无需 npm install，浏览器依赖和模型位于 vendor。Windows 也可运行“启动花园.bat”。

发布 dist 目录即可，包含 index.html、模块、带内容哈希的无损 WebP 和本地模型。Netlify 配置已提供；手动上传必须上传 dist 内的完整内容。公开访问必须使用 HTTPS。静态构建不包含旧 PNG、开发文档或测试人像。

## 体验

1. 开启摄像头并允许访问；面部保持完整、光线足够。
2. 默认手机竖屏，可切换到 16:9 电脑横屏。微笑触发阈值默认 10%，支持滑杆在 5%–90% 调节并保存在本机；越低越容易触发。
3. “笑意绽放”显示实时大笑强度，烟花触发阈值默认 60%，可在 50%–90% 独立调节并保存在本机。张嘴大笑触发烟花，持续大笑最多三朵；花园约 1 秒淡出。
4. 大笑转微笑后，等待每枚烟花约 60% 主体粒子完成飞行再恢复降雨；仍在升空的新烟花继续阻塞。落水、转换为爱心/星星或失效离场均算完成，少量残留互动不会无限阻塞。
5. 托起一只手可接爱心/雨滴，接住后出现星星；手移动影响邻近散落星光，快速挥手可抛出掌上星星。
6. 雨滴和烟花实际落水后出现涟漪，烟花水面为底部 7.5% 浅蓝蜡笔背景。

开启摄像头后，通过真实表情触发降雨和烟花。纯净画面适合浏览器窗口捕获，Escape 或触屏显示的退出按钮可退出。

右侧“手机竖屏 / 电脑横屏”切换到 iPhone 15 Pro 屏幕比例：1179×2556，等比布局参考 393×852（[Apple 技术规格](https://support.apple.com/zh-cn/111829)）。真实画布随之调整，摄像头保持居中 cover 裁切，面部/手掌仍使用相同坐标映射。手机框、灵动岛及直播评论/操作区为界面示意，不会开播；纯净画面隐藏这些示意并保留屏幕比例。竖屏雨滴与拖尾为原不透明度的 66%，生成速率为 62%，最短拖尾加长；切换电脑横屏恢复桌面参数。

## 设计与工程

手机竖屏新生雨滴尺寸缩小 20%，拖尾长度层次保留。反弹爱心下降穿过水面时也会变成蜡笔星星，触发蓝色水面、水花与涟漪；手掌接住优先，水面星星继续使用总量与邻近落点限制。

手机竖屏中大株花草再缩小 20%，前后两层最多显示 10 株。后排根部在画面高度 92.6%–94%，尺寸再乘 .82、透明度再乘 .74；前排根部在 97.8%–99.2%。同排保留间距，跨排允许适量交叠并横向错开，按根部远近绘制；手拨动碰撞随根部与尺寸一起调整。已有电脑花园切入竖屏会选择分布合适的组合，切回电脑恢复完整显示。

- 高株偏向两侧，中间穿插低株；蜡笔花草有高度、透明度和生长节奏差异，最多 36 株且随宽度控制。
- 烟花整朵旋转轮廓避开头部；两种主色配奶油高光，成对烟花错开 0.9 秒；旧烟花在恢复下雨时减弱装饰亮度，物理继续运行。
- Worker 优先、CPU 推理；人脸先就绪，手势随后加载。Worker 环境不可用时回退主线程 CPU；资源下载失败明确结束等待，允许重试。
- 采样最长边 640；限制单帧在途，摄像头帧去重，渲染最高约 60fps。实际速度取决于设备。
- 纹理缓存、粒子上限、连续碰撞、手势滤波、过期结果清理与资源失败回退。
- 主要蜡笔素材无损 WebP 比原 PNG 减少约 44%，欢迎图改用同风格小图。内容哈希资源可长期缓存，脚本和 HTML 必须重新验证。
- 尊重减少动态效果设置：去掉爆炸闪光、降低光晕烟雾、取消粒子周期闪烁，保留碰撞反馈。

## 1.5 发布恢复

图片失败最多自动尝试三次，之后停止请求；网络恢复或点击预览内重试，仅补载失败素材。视频暂停和停帧与丢脸分别处理，先尝试恢复播放，需要重开时由用户点击；用户主动关闭后不会自动开启。手机预览内显示简短准备/失败状态，正常识别后隐藏。手势失败单独记录 handFailed，不冒充 handReady。

发布前自动执行有界重试、视频恢复、图层唤醒/清理和表情延迟回归，测试与构建成功后再更新 Pages。开发依赖由 package-lock.json 固定，线上仍为静态页面。当前证据与待测范围见 [验证记录](验证记录.md)。

## 诊断与验收

普通页面隐藏 FPS。地址附加 ?debug=1 可查看绘制帧率、脸/手识别频率与采样至应用的 p95 延迟；控制台 gardenDiagnostics() 提供更多只读数据。识别频率不是摄像头帧率，绘制帧率也不是识别准确率。附加 ?safe=1 显示直播头像/聊天/礼物/底部操作区验收示意，不代表已接入直播平台。

当前 104 项规则测试通过；浏览器测试默认用纯色画布生成视频流，真实 MediaPipe 模型参与，另有受控识别结果验证响应时序。烟花视觉分层另用确定时间的 Canvas 渲染检查。真实手机、真人多样性和线上冷启动仍须按 真机验收表.md 完成，不宣称全机型准确。最新性能证据见 [ROI 优化记录](docs/ROI优化-2026-09-14.md)。

### 烟花视觉分层

在同色深色烟云之上，用双色蜡笔色块呈现星球、星环、爱心和鲸鱼，再叠加明暗不同的粒子。图案在 1.05 秒炸开时于 .22 秒内整图淡出，不生成大块色片；物理粒子自然散开、继续落下、碰头变爱心、被手掌接住。主体不进入碰撞池或降雨恢复计数。四种主体共享缓存，视觉事件最多三枚，各画质档位均使用相同的快速淡出。雨滴、爱心和星星加入缓存暗边与亮边。

### 1.4 优化与浏览器回归

- 现有镜头状态区显示授权等待、模型准备、首帧识别、面部入镜及重试提示；不恢复已移除的面板。
- 手机评论和操作区使用缓存软遮罩局部减弱装饰；纯净画面关闭遮罩。花草根部、拨动及粒子碰撞保持同一坐标。
- 烟花主轮廓粒子增大约 12%，弱装饰减小，减少星球内部填充及外围杂点；接触提示位于装饰粒子上方。
- 人脸结果先发回；常态计划间隔 110ms，烟花活跃时 80ms。手势未出现时每 160ms 探测，出现后计划间隔 40ms，短暂丢失保留 450ms 快速探测。实际频率受视频帧和设备计算耗时限制。
- 主线程回退先呈现人脸结果再初始化手部；同轮脸/手推理之间让出一帧。模型初始化及同步推理仍可能卡顿，不能据此承诺低端手机全程 30fps。
- 花园布局缓存；雨景、植物和烟花共用 1.75 / 1.35 / 1 的画布像素密度上限。模型本地服务器缓存 1 天，源码用 ETag 重新验证，托管配置已有对应缓存规则。
- `?debug=1` 增加头部代理轮廓；`gardenDiagnostics()` 提供脸/手各自延迟与推理 p95、首次可用时间、实际相机分辨率和资源加载记录。图像不上传；诊断中不包含设备 ID。

浏览器测试是开发依赖，线上运行仍无需 npm install：

```sh
npm install
npx playwright install chromium
npm run test:browser
```

测试自动启动并关闭 4187 端口的本地服务器。默认用纯色画布流检查加载、权限恢复、布局和失败处理。设置 `FACE_FIXTURE` 为自己有权使用的本地 JPEG 路径，可额外验证真实模型识别与人脸离场；图片不会进入源码或 dist。`BROWSER_PATH` 可指定已有 Chrome；`DEMO_URL` 可改用已有预览，`PLAYWRIGHT_MODULE` 适用于已有共享测试运行时。输出位于忽略提交的 `test-results/`。测试流不代表真人摄像头和真机验收。执行入口见 `tests/browser/acceptance.mjs`。

## 已知范围与排错

- 当前单人、单手。头顶使用面部关键点推算的椭圆碰撞体，不是头发分割；帽子、遮挡、侧脸和人物过小可能影响体验。
- 检测的是面部表情特征，未用声音确认真实笑声。讲话、自然表情、大笑的误触发需真人样本验证。
- 不弹权限：在 HTTPS 顶层页面及系统浏览器中打开；检查系统相机权限。嵌入 iframe 时还需要宿主授权摄像头。
- 权限拒绝或设备占用：允许网站权限或关闭独占摄像头的应用，再开启。
- 手势暂不可用：表情效果仍可运行，可用鼠标/触屏拨花；关闭再开启会重试失败的手部模型。
- 人脸未找到：靠近镜头、完整入镜、补足光线；系统不在丢脸时继续使用旧碰撞体。
- 本原型未实现虚拟摄像头、透明 OBS 浏览器源或平台专用 SDK。实际直播同时编码、摄像头占用和礼物区布局需另验。
