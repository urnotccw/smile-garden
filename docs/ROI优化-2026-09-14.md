# ROI：保留画面，减少无效绘制

本轮以提交 `5c7cd3e248eca9f637992026708c7b832167a613` 为基线。这里的 ROI 指视觉与互动体验相对于算力、流量和维护成本的收益，不是图像识别的 Region of Interest。

## 已完成

- 草地缓存从整屏改为底部绘制区域，保留透明取样边缘、原画布坐标、蜡笔纹理随机种子与渐变。相同尺寸的 ResizeObserver 回调及画质切换复用纹理，不再重新生成。
- 直播评论/操作区的软遮罩只存储并绘制底部区域，人物和其他区域不做无效遮罩合成。
- 雨景与烟花分层按内容绘制。最后一帧消失后清空一次再休眠；新内容下一帧立即唤醒。物理、识别、碰撞与状态计时仍照常推进。
- 绘制存活条件包含烟雾、色光、水面渐隐、碰撞提示和独立的手掌接雨星星，避免只判断烟花粒子数量导致尾段消失。
- 没有新增运行依赖，没有削减图案、粒子数量、纹理分辨率或模型精度，没有修改表情阈值与 60% 落地衔接规则。

## 前后测量

Windows 桌面 Chrome headless、本地 HTTP 服务、DPR 1。缓存测量使用指定画幅；待机测量使用默认竖屏、1280×1000 浏览器视口、素材完成加载后连续采样 1.5 秒，不开启摄像头。

| 指标 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 393×852 草地缓存像素 | 334,836 | 54,234（减少 83.8%） |
| 1200×675 草地缓存像素 | 680,900 | 111,100（减少 83.7%） |
| 单份直播软遮罩缓存像素 | 65,536 | 12,800（减少 80.5%） |
| 三个特效画布待机 clearRect 调用 / 1.5 秒 | 267 | 0 |
| 三个特效画布待机 drawImage 调用 / 1.5 秒 | 178 | 0 |

像素数是对应离屏缓存的尺寸，不是整个应用的内存降幅；调用数不是实际 GPU 耗时或电量。活动特效仍按原节奏绘制，不能把待机节省推广为“整站性能提升 84%”。旧版待机调用次数会随运行环境帧数略有变化。

核对线上 HTTP 响应时发现 GitHub Pages 已经 gzip 压缩 WASM 和模型：SIMD WASM 原文件 9,574,032 字节，对应响应 Content-Length 2,945,420 字节。因此没有额外引入客户端压缩包、解压和兼容回退代码，也不把已有 CDN 压缩计作本轮收益。

## 视觉和功能验证

- 横竖两种画幅的新旧遮罩逐像素一致。
- 草地在相同画幅、DPR 和原随机种子下比较预乘 Alpha 像素：平均每通道差异分别约 0.0100、0.0088 / 255，最大约 2.76 / 255，属于裁剪后的细小边缘取样差异；已查看竖屏花园截图，颜色、范围和蜡笔质感保留。
- 101 项规则测试通过，包括低帧率生长、60% 落地恢复降雨、头部碰撞、手掌接雨和长时间粒子数量限制。
- 浏览器回归通过：横竖屏布局、旧设置迁移、摄像头拒绝后恢复、Worker/主线程模型启动、识别结果延迟与丢脸恢复。
- 新增绘制回归：花园唤醒与清空、仅剩水面、仅剩烟雾、仅有手掌雨滴星星、尾段清空后无重复绘制。

这些是桌面浏览器自动测试与合成场景，不是微信真机或真人识别准确率测试，也没有实测手机温升、电量和全链路首帧提升。真机长时间直播仍应按项目的真机验收表检查。

## 复现

安装开发依赖与 Playwright 浏览器后：

```sh
node --test tests/*.test.mjs
npm run test:render
node tests/browser/measure-render.mjs
node build.mjs
```

测量结果写入 `test-results/render-cost.json`。对比旧版时，在另一个检出目录运行上述基线提交的本地服务，将 `DEMO_URL` 指向该服务，用本版的 `measure-render.mjs` 再采样一次。不要传入 `?debug=1`，它会主动绘制调试轮廓。绘制回归使用合成状态推进真实应用循环，没有把演示入口重新加入产品。
