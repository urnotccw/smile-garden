# 识别与首帧降雨响应（2026-09-13）

本次针对短暂丢脸反复重置微笑、慢设备的有效表情结果被丢弃，以及雨滴从画外进入造成的视觉等待进行修正。

- 280ms 内短暂丢脸保留已有微笑状态，停止沿用头部风向；缺失时间不计入新微笑的确认时长。持续丢脸清空状态，回来需要重新确认。
- 微笑平滑时间常数由 100ms 调整为 80ms，确认时间由 180ms 调整为 120ms。单次强分数不会直接触发；阈值及放松退出规则保持不变。
- 表情结果最多接受 700ms 延迟；超过 350ms 的头部坐标仍不参与碰撞。过旧结果被丢弃但不再重置整个交互；连续 1000ms 没有可用结果时释放表情状态，显示识别稍慢，后续有效结果自动恢复。摄像头关闭、切换及后台恢复仍执行完整重置。
- 微笑确认后的下一次更新先生成两滴位于画面顶部的雨，其余雨滴继续原有渐入、密度和运动。短暂波动不会重复堆积首批雨滴。
- 烟花仍优先，60% 主粒子完成降落后才允许接雨；草地铺开再长花的顺序保持不变。

验证：87 项 Node 自动测试通过，静态构建通过。浏览器回归覆盖两档桌面窗口、390px 手机布局、权限恢复、真实模型加载、Worker / 主线程回退；没有页面异常。`npm run test:tracking` 另外以受控模型输出来验证实际页面的短暂丢脸、持续丢脸、500ms 延迟接受、900ms 过旧丢弃、超时停止和恢复，确认没有重新初始化 Worker。

这些结果证明状态与时序逻辑通过回归，不代表所有设备的真人识别准确率或固定端到端响应时长。暗光、遮挡、侧脸、真机发热及直播编码同时运行仍需真人设备验收。
